5.1.1
-----
* SCUMM v8 (The Curse of Monkey Island) viewer fixes. Selecting the LFLF node of a v8 game no longer crashes - the LFLF and the room node now open the dedicated v8 room-image viewer, instead of the v5/v6/v7 room viewer that expected a room-image (RMIM) block v8 does not have (v8 nests its images differently). Selecting a v8 font no longer raises an internal error while gathering room palettes (v7/v8 rooms do not use the v5/v6 palette block).

* v8 localized text now shows the correct accents. The Curse of Monkey Island is a Windows-95 game, so its LANGUAGE.TAB uses the Windows-1252 (ANSI) code page, not the DOS CP850 that the v1-v7 games use; the "Texts (localized)" viewer was decoding it as CP850 and garbling every accent (for example "cao" with the proper marks showed as "þÒo"). It now picks the right code page per edition - Windows-1252 for v8, CP850 for v1-v7 - for both the on-screen display and the write-back.

* The external sound files are grouped in the tree. The iMUSE sound bundles, the speech file and the CD audio now appear under a single "Sounds" node (like "Texts (localized)") instead of at the top level. Display only - it does not change the files or the engine.

5.1.0
-----
* SCUMM v1/v2 translation fix - object dialogue was being dropped from the export. In Maniac Mansion and Zak McKracken (both the v1 and the v2 "Enhanced" releases), the text an object shows when you use, look at or read it (the object verb scripts) was missing from the exported translation file. The name string of an object is packed immediately before its verb code, and the exporter was ending the verb code at that name - which left an empty range and silently discarded every verb-code line of every object in the game. The verb code is now bounded above its verb entry instead of the object start (the same way the v3 EGA games already did it), recovering the full object dialogue - hundreds of lines per game that were previously untranslatable, for example the character biographies on Maniac Mansion's kid-select screen and the "no trespassing" sign. Both the export and the write-back were fixed, and the same fix covers every v1 and v2 game.

* v1/v2 re-import is now a true no-op. Importing an unedited export used to report every line as "changed" and rebuild every block. The v1/v2 text codec folds a trailing space into the preceding letter, so decoding then re-encoding an untouched line produces an equivalent but not byte-identical sequence; the importer now compares the decoded text, so an unchanged line is left exactly as it was and only real edits are written back.

* v1/v2 scripts that end in a dead, size-clipped instruction are now editable. A few scripts carry leftover, never-executed code after their final stopScript whose last instruction is clipped a byte short by the resource boundary; the disassembler used to treat that as a failure and exclude the whole script from translation. It now recognizes a harmless trailing clip and keeps the script editable, while still rejecting a genuine decode error.

* v1/v2 export charmap header now omits any accent slot the game itself uses. The Portuguese accent map parks each accent on a punctuation slot; in Maniac Mansion and Zak McKracken one of those slots (the "*" used for u-acute) is also used literally by the save-game UI labels ("Game A" .. "Game J"). The export now detects that and drops the colliding accent from the "; charmap:" header, so the exported text shows the literal character instead of a false accent and the header only advertises slots that are genuinely free. (A dropped accent can be re-mapped to a free slot by hand in the header if it is needed.)

* Note for translators - the sentence-line connector words ("with", "in", "on", "to", as in "Use key with door") are not stored in the v1/v2 game data at all. They were hard-coded in the original executable per language, so they cannot be translated by editing the data files, and ScummVM substitutes its own built-in set (which has no Portuguese). This is a limitation of the games, not of the editor.

5.0.0
-----
* SCUMM v8 support. The Curse of Monkey Island (1997) can now be opened, viewed and edited with the same feature set as the v1-v7 games plus the extras it needs - completing coverage of the whole classic SCUMM line, v1 through v8. As always it is recognized from the content of its data files alone, never the EXE: v8 keeps the v6/v7 tagged IFF container (not obfuscated) but spreads the game over a separate index file (COMI.LA0) and TWO data files (COMI.LA1 + COMI.LA2), with a wider index (32-bit directory counts, a 168-byte MAXS, a 46-byte object directory and a v8-only room-scripts directory). All eight editions - the CD release plus Chinese, French, German, Italian, Korean, Portuguese and Spanish - round-trip byte-for-byte.

* v8 game text translation. The Curse of Monkey Island uses a completely new bytecode language (a fresh opcode table with 4-byte operands throughout), so the editor gained a dedicated v8 disassembler; the global scripts, room entry/exit scripts, local scripts and the object verb scripts all disassemble and export/import for translation, with the 4-byte jumps and the v8 8-byte verb offset table remapped automatically when a translation changes length - the same workflow as every other version.

* LANGUAGE.TAB - the high-value translation file. Almost all of COMI's on-screen text (about 10,000 lines) lives in an external plain-text LANGUAGE.TAB rather than in the container; the editor exposes it under the "Texts (localized)" node, edits it line by line preserving the %variable% runtime tokens and the /voice-tag/ prefixes, and writes it back with a byte-identical round-trip. Accented characters display through the edition's DOS code page (CP850 for Portuguese and the other Western releases), and the release language is detected automatically from the file's content.

* v8 room and object images. Backgrounds, object images and the walk-behind (z-plane) masks reuse the v5/v6/v7 picture codecs (SMAP strip, BOMP and the z-plane mask RLE) through v8's new IMAG/WRAP/OFFS container nesting; both the SMAP- and BOMP-coded objects and the z-planes are decoded, exported as lossless indexed PNGs and imported back, with the strip offset tables rebuilt for an edit of any size. A dedicated v8 room-image viewer shows the background, each object and each z-plane per node, alongside the batch graphics pass.

* v8 costumes and fonts. COMI reuses the AKOS costume format (decoded, viewed and re-encoded like v7) and ships its fonts as external FONT0-4.NUT SMUSH fonts (decoded, exported and imported through the same .NUT pipeline as The Dig and Full Throttle).

* v8 sound. The speech and music inside the container (iMUSE iMUS PCM) play and export to WAV, as do COMI's external MUSDISK/VOXDISK iMUSE bundles - which use the VIMA variable-bitwidth IMA-ADPCM codec that the v7 bundles did not, now fully decoded. As with v4-v7, sound is play/export only.

* Engine-wide cross-version validation. Every one of the 28 game editions across v1-v8 was loaded and round-tripped byte-identically (index and data), and a five-lens adversarial review checked every subsystem of every version against the matched ScummVM source and real game bytes. The whole editor passed; a small number of real issues found during the review were fixed (a classic-costume decoder that could overrun the last column on a few v5/v6 frames, the v8 object viewer's verb-code disassembly, and a missing control-byte guard in the v1/v2 text codec). The edited Curse of Monkey Island was also booted in ScummVM with every image, font and text edited and subtitles on, confirming the edits render and the game runs.

* Known limitations. Importing edited sound is not yet available (the same as v4-v7). The SMUSH cutscenes (.SAN) are listed but not edited. The Curse of Monkey Island is a Windows-95-only title (there was never a DOS build), and its original 1997 executable does not run on modern Windows, so ScummVM is the engine used to verify edits - it is also how the game is played today. As with every version, an edit that changes the size of the index file changes its checksum, so ScummVM's automatic detection may need the new checksum.

4.0.0
-----
* SCUMM v7 support. The Dig and Full Throttle (1995) can now be opened, viewed and edited with the same feature set as the v3-v6 games plus the extras these two need - extending coverage from v1 all the way to v7. As with every other version they are recognized from the content of their data files alone, never the game EXE: v7 keeps the same tagged IFF container as v5/v6 (the engine is a direct extension of v5/v6), split across a separate index file (.LA0) and data file (.LA1), and the container round-trips byte-for-byte across all 24 editions of the two games (every language release tested).

* v7 game text translation. Object and location names, verb scripts, the room entry/exit scripts and the global scripts all disassemble and export/import for translation, with the tables and jump offsets remapped automatically when a translation changes length - the same workflow as every other version. The v6 script disassembler was completed for the handful of v7-only opcodes (including the two-byte local-script id).

* Localized text - the high-value translation feature for these two games. Unlike the earlier games, The Dig and Full Throttle keep most of their on-screen text OUTSIDE the game container, in separate files: The Dig's dialogue in LANGUAGE.BND (lightly obfuscated) and both games' subtitle and interface text in .TRS files (plain, or in the ETRS/obfuscated form some releases use). The editor now exposes all of it under a new "Texts (localized)" node, decodes the obfuscation transparently, and writes it back with a byte-identical round-trip - so a translation of the actual spoken/subtitle text can be edited in place. This is the text most translators care about and it was previously unreachable.

* Accented characters in the localized text now display correctly. v7 stores text in the original MS-DOS code page (code page 850 for the Western releases, including Brazilian Portuguese), so the editor transcodes it for display and on save - an "ã", "ç" or "ü" shows as itself instead of a raw byte, matching what the real engine draws.

* v7 room and object images. Backgrounds, object images and the walk-behind (z-plane) masks reuse the v5/v6 picture codecs (the SMAP strip format and BOMP), decoded against the room palette and exported as lossless indexed PNGs; an edited PNG imports back the same way it does for v5/v6.

* v7 costumes (AKOS). The Dig and Full Throttle use the later AKOS costume format rather than the classic one; its cels are decoded (the three codecs these games use - run-length, BOMP and the bit-packed MAJMIN), shown in the costume viewer and exported as PNGs, both per-resource and in the batch graphics pass, and edited frames import back into the original codec.

* v7 fonts. Both the fonts stored inside the game container (shown and edited exactly like the v3-v6 charsets) and the external .NUT SMUSH fonts (The Dig and Full Throttle each ship several) are decoded, exported as glyph atlases and imported back. A re-encoded .NUT is written in the exact layout the real engine's font loader expects, so an edited font stays loadable - verified by reproducing the engine's own two-pass frame walk and pixel decode over every glyph of every .NUT in both games.

* v7 sound. The speech and music stored inside the container (the iMUSE iMUS PCM format and Creative VOC) play in the viewer and export to WAV, as does Full Throttle's MONSTER.SOU speech file (its per-line VOC, including the lip-sync wrapper) and The Dig's .BUN iMUSE bundles (DIGMUSIC.BUN / DIGVOICE.BUN, whose LZ/delta/12-bit-repack compression is fully decompressed). As with v4-v6, sound is play/export only - importing edited audio is not yet available.

* v7 games appear in the resource browser as a full block tree with the same per-resource viewers as the v2-v6 games, and the language of a v7 release is detected automatically (from the localized text for The Dig, from the container scripts for Full Throttle).

* Engine-wide validation: all 24 v7 editions of the two games were loaded and had every image, costume, font and sound decoded through every viewer with no failures; and a copy of each game was edited end-to-end at once - dialogue and names, fonts, backgrounds, objects and costumes - then booted in both ScummVM and the original DOS interpreter under DOSBox, confirming the edits render and the games run.

* Known limitations. Importing edited sound is not yet available (the same as v4-v6). The SMUSH full-motion cutscenes (.SAN) and the original-DOS support binaries that ScummVM reimplements are listed but not edited. As with every other version, an edit that changes the size of the index file changes its checksum, so ScummVM's automatic detection may need the new checksum (a size-neutral edit keeps it identical).

3.6.1
-----
* Fix (critical): importing an edited image back into a v1 game (Maniac Mansion / Zak McKracken in their original 1987/1988 form) produced a game the real engine could not run - it started to a black screen under both the original DOS interpreter and ScummVM. The room was being rebuilt by appending the re-encoded picture data and leaving the old data behind, which roughly doubled the room, and the v1 engine cannot load a room that grew like that. Rooms are now rebuilt compactly - the picture data is re-compressed in place and every internal offset re-pointed - so an edited room stays close to its original size and the game runs. Confirmed by running an edited Maniac Mansion in DOSBox.

* Importing edited v1 OBJECT images and object walk-behind (z-plane) masks works again (they were briefly export-only while the compact rebuild was finished). Where several objects share one piece of picture data - which the original games do, reading the same bytes at different sizes - an edit re-encodes the shared picture so every object that uses it stays valid. As before, an edit that cannot fit v1's format (more than 256 distinct tiles, or more than four colours in a cell) is rejected with a clear message rather than silently corrupted.

* Stress-tested by stamping a coloured mark on every background, object and costume of a copy of Maniac Mansion at once (hundreds of edits) and confirming the game still boots to character-select and renders the marks in DOSBox, with rooms staying compact.

3.6.0
-----
* Fix (important): batch-exporting a v1 game (Maniac Mansion / Zak McKracken in their original 1987/1988 form) produced corrupted images and costume frames. The batch path decoded the v1 C64-style tilemap with the v2 picture codec; v1 now has its own batch export/import that uses the correct codec, matching what the per-resource viewers already did. The exported PNGs are pixel-identical to the single-resource export, and an unmodified export re-imports as a clean no-op.

* Fix: Japanese (and other Far-Eastern) text in the v4-v6 games could be corrupted on export/import. The byte 0xFE is a string-control escape only in the v3 EGA games (Loom, Indiana Jones 3) - in v4-v6 it is ordinary text (a legal Shift-JIS trailing byte). The text codec now treats 0xFE as an escape only where it actually is one, so Japanese releases round-trip exactly.

* New: per-glyph X/Y offset editing for fonts (the equivalent of scummtr's FontXY). The viewer's new 'Export X/Y' / 'Import X/Y' buttons write the per-character draw offsets to a small text file you can edit and re-import - so you can adjust a glyph's position or kerning (for example to make a translated accent sit right) without redrawing its bitmap. Character width/height still come from the PNG atlas; this only moves the glyph.

* v2 object walk-behind (z-plane) masks are now included in the BATCH export/import, not only the per-resource viewer - so a translation that touches object masks can be processed in one pass like every other version.

* Engine-wide validation: the whole game library, including every edition under 'Other Languages' (French, German, Italian, Spanish, Japanese, Hebrew, Brazilian, FM-Towns), was loaded and had every image and costume frame decoded with no failures; the costume codec gained a pixel-lossless round-trip test for the v4/v5/v6 games.

* Known limitation unchanged: as before, an edit that changes the size of the index file changes its checksum, so ScummVM's automatic detection may need the new checksum (a size-neutral edit keeps it identical).

3.5.1
-----
* Editing v1 and v2 images back in is now complete. Importing edited v1 OBJECT images and walk-behind (z-plane) masks is now supported, alongside the room backgrounds and costumes that were already importable in 3.5.0; v1 per-object masks - which the original DOS engine does keep, one per object - are now decoded, exported and imported as well. v1 stores the room background and every object image against one shared tile set, so the importer preserves that set and only adds the tiles an edit needs, leaving every other image in the room untouched. An edit that cannot fit v1's format (more than 256 distinct tiles, or more than four colours in a cell) is still rejected with a clear message rather than silently corrupted.

* v2 object walk-behind masks now import too (they already exported). With this, every per-resource viewer that can export an image can also import it back, across every version from v1 to v6.

* Fix (important): importing a v1 room background corrupted the room's object images. Because the background and every object image share one tile set, re-encoding a background used to rebuild and renumber that set, leaving every object in the edited room pointing at the wrong tiles. Backgrounds now keep the existing tile set intact, so editing a background no longer touches any object.

* Fix: a v1 image edit that needed a new tile could disturb an unedited part of the same image, and the importer could be coaxed into writing over an object that has no real image. Both are corrected - an unedited region is now guaranteed untouched, and an imageless object is refused on import just as it is when decoding.

Maniac Mansion and Zak McKracken in their original 1987/1988 DOS floppy "classic" form can now be opened, viewed and edited - the oldest games the editor handles, completing coverage from v1 to v6. As with every other version they are recognized from the content of their data files alone (never the game EXE): the classic 00.LFL index has its own magic and, unlike every later version, stores NO resource counts at all - they are hardcoded per game - which the editor now reproduces. * v1 scripts and text translation. v1 shares the byte-oriented script language of v2 (with one small opcode difference the editor now handles), so object names, verb scripts, the entry/exit scripts and the global scripts all disassemble correctly and export/import for translation, with the tables and offsets remapped automatically - the same workflow as every other version. Importing edited v1 OBJECT images and walk-behind masks is not yet available (those stay export/preview only). v1 text and the EXE font are fully editable. v1 sound is PC-speaker data with no music track to play, so it is listed and exported raw only.

* Known limitation. As with the v2/v3 games, an edit that changes the size of the index file changes its checksum, so ScummVM's automatic detection may need the new checksum (a size-neutral edit keeps it identical). The v1 EXE font shows only under the original DOS engine (DOSBox), as ScummVM substitutes its own.

3.0.0
-----
* SCUMM v2 support. Maniac Mansion and Zak McKracken (the enhanced floppy releases) can now be opened, viewed and edited with the same feature set as the v3-v6 games - completing coverage of every SCUMM version from v2 to v6. As with every other version, they are recognized from the content of their data files alone, never the game EXE. v2 reuses the same "old bundle" on-disk container as the v3 EGA games (a 00.LFL index plus XOR-encrypted, untagged room files that hold the rooms, scripts, sounds and costumes); the only structural difference is the one-byte-per-object room table, and every container round-trips byte-for-byte.

* v2 room and object images. The 16-colour EGA backgrounds and object images are decoded against the fixed EGA palette (v2 has no per-room palette) and exported as lossless indexed PNGs; an edited PNG imports back with only the changed 8-pixel columns re-encoded, so an untouched image stays byte-for-byte identical and a translated one differs only where it was painted. The z-plane (walk-behind) masks export and import as black/white PNGs too.

* v2 costumes and scripts. Costume frames are decoded and individual frames can be edited and imported back. A new byte-oriented v1/v2 script disassembler decodes every script - object verb code, local scripts and global scripts - in the early SCUMM bytecode, a different language from v3-v6 in which each opcode carries its own parameter layout.

* v2 game text translation. Object names, verb scripts and inline dialogue export and import, with the tables and jump offsets remapped automatically when a translation changes length - the same workflow already available for v3-v6. The v2 string format packs a "trailing space" flag into each character byte, so the export uses a readable token form that re-encodes exactly on import.

* v2 fonts are editable - and they live inside the game EXE. Unlike v3-v6, where the fonts are separate LFL files, the v2 font is embedded in the executable; the editor finds it, decompresses it, shows it as an editable glyph atlas and patches the edited glyphs back into the EXE in place. Because the v2 font is 7-bit with no free slots, a translation's accented letters are parked on rarely-used punctuation slots (redrawn in the font), configured through a "charmap" line in the text export so the team can tune it.

* The v2 and v3 "old bundle" games now present their contents as a full block tree, exactly like the v4-v6 games, instead of the earlier descriptive text. Every resource - rooms and their headers, backgrounds, object images and masks, object verb code, local and global scripts, sounds and costumes, and the index directories - is its own node with a dedicated viewer, and images and costume frames can now be imported back from the viewer itself (per node), not only through the batch action.

* Game and language detection were rebuilt around the file content. Every supported game (v2 through v6) and its release language are now identified from the data alone: a checksum (MD5) of the index file is matched against a table derived from ScummVM's database, then refined by a heuristic that reads a sample of the game's own dialogue - which also catches fan translations that kept the original English index, where the checksum would otherwise report English. Validated across the whole game library (over a hundred editions, in every supported language) with no misdetection. The displayed game name now covers every supported title, so Indiana Jones 3, Zak McKracken and Maniac Mansion are no longer shown as "None".

* The editable font atlas now draws a consistent grid across every version - the v2 EXE font, the v3 charsets and the v4/v5/v6 fonts - with a guide so each 8x8 glyph cell is easy to line up when redrawing characters.

* Fix: the v3 walk-behind (z-plane) mask support was completed and corrected, so the EGA masks of the v3 games export and import reliably.

* Known limitation - the v2 EXE font in ScummVM. An edited v2 font is written correctly into the game EXE and is shown in the editor, but ScummVM substitutes its own built-in font for these games and will not display the edited one; the embedded font has to be checked by running the game natively (for example in DOSBox). As with the v3 games, an edit that changes the size of the index file changes its checksum, so ScummVM's automatic detection may need the new checksum - keeping a translation size-neutral leaves the index byte-for-byte identical and avoids this.

* The automated xUnit test suite was extended to match: v2 detection and byte-identical save round-trips, the v1/v2 disassembler, the v2 image and z-plane codecs, the EXE-font extract and patch, the accent charmap, the old-bundle block tree and its per-node imports, and the library-wide language detection - all run against the real library of games.

2.5.0
-----
* SCUMM v3 support. Indiana Jones and the Last Crusade, Loom and Zak McKracken can now be opened, viewed and edited. v3 comes in two very different on-disk forms and both are detected from the data files alone (never the game EXE): the 256-colour "small header" games (Indy3 VGA, and the FM-Towns CD releases of Indy3, Loom and Zak - one NN.LFL file per room, a plaintext 00.LFL index and 9N.LFL fonts) and the older XOR-encrypted EGA games (Indy3 EGA, Loom EGA - a 00.LFL index plus untagged room files). Both get the full feature set below - images, fonts, costumes, sound and text all export and import - and every container round-trips byte-for-byte. Every release of all three games - all languages and graphic editions - is identified correctly (the game is told apart by its charset count, which is stable across editions, since the FM-Towns builds pad their resource directories to identical sizes).

* v3 room and object images. The FM-Towns/256 backgrounds and object images (compression codecs 1-4 and 7) and the EGA backgrounds and object images are decoded and exported as lossless indexed PNGs, and an edited PNG can be imported back: only the changed 8-pixel columns are re-encoded - so an untouched image stays byte-for-byte identical and a translated one differs only where it was painted - with the 256-colour games re-encoding as raw pixels and the EGA games as 16-colour strips. Their z-plane (walk-behind) masks export and import too.

* v3 costumes, scripts and text. Costume frames decode with the room palette and individual frames can be edited and imported back; a new v3 script disassembler (v3 shares the parameter-bit language with v4/v5 plus a handful of its own opcodes) decodes every script - object verb code, local scripts and global scripts - in full across all three games and both on-disk forms; and object names, verb scripts and dialogue can be exported and imported for translation, with all tables and jump offsets remapped automatically when a translation changes length.

* v3 fonts are editable. The 9N.LFL charsets are shown as a glyph atlas, and a new "Export/Import PNG" pair writes an editable 16x16 grid of the 8x8 glyphs so the accented characters a translation needs can be drawn in an image editor and imported back (extending the font when a new slot is filled).

* The batch "Export/Import Game Graphics" and the per-room image, costume, font and sound viewers all work on v3 games, reusing the v4 pipeline; an unedited export/import round-trips every room file byte-for-byte.

* Fix: a room palette is now read at its declared size instead of always assuming 256 colours, so the 16-colour rooms in Loom's FM-Towns release no longer shift when the file is re-saved (this also makes any future palette edit safe). A v3 index that ends with trailing padding (Indiana Jones 3 FM-Towns) now loads instead of failing.

* Known limitation - running an edited Loom EGA (Floppy v1.1) in ScummVM. This is a ScummVM detection issue, not bad data: the edited game is valid and opens correctly in the editor. ScummVM recognizes a SCUMM game by a checksum (MD5) of its index file (00.LFL). Any edit that changes that file's contents - a translation whose text is a different length, or an image that re-compresses to a different size - changes the checksum, and ScummVM then falls back to a heuristic that guesses the game from which room files are present. That heuristic accepts the edited data for every other v3 edition, but it specifically rejects Loom Floppy EGA v1.1: this release ships both 84.LFL and 86.LFL, and the heuristic's rule for Loom requires exactly one of those two files, so it concludes the folder is "not Loom" and reports "Game data not found". The workaround is to keep the edit size-neutral - a translation kept to each string's original length, plus font edits and image edits that fit within the original size - which leaves 00.LFL byte-for-byte identical so ScummVM still matches the original checksum and runs the edited game (verified running in ScummVM with edited text and fonts visible in-game). A length-changing translation of this one edition otherwise needs its new checksum added to ScummVM's database, the same way other fan translations of these games are already supported.

* New SCUMM v4 script disassembler. v4 shares the v5 parameter-bit language with a handful of its own opcodes; every script and every object verb script of Monkey Island 1 and Loom decodes 100%, rendered in the same readable C#-like listing.

* All remaining v4 block types are decoded with a viewer (colour cycling, EGA shadow palette, walk boxes, scale slots, local-script/object/sound lists) - nothing is left as a raw "not implemented" block. For readability the local scripts (LS) are shown nested under the local-script count block (LC) that declares how many of them the room has.

* v4 sound viewer with playback and export. An AdLib music track plays as a melody preview (its embedded MIDI is rendered through the Windows synthesiser; export the raw resource for the real OPL2 sound), and every WA/AD sub-block can be exported, one or all at once.

* Detection from the data files alone (never the game EXE, which may be missing from the folder): Loom CD is told apart from Monkey Island 1 floppy by its CD audio and single data disk, the Japanese FM Towns release of Monkey Island 1 (MONKEYK.000) is recognized, and the displayed language now covers the v4 games as well as the Japanese (SJIS) editions.

* Japanese (SJIS) text now decodes correctly. A string-parsing fix (0xFE is an ordinary character, not an escape code) makes the Japanese editions of Indiana Jones and the Fate of Atlantis and Monkey Island 2 disassemble their scripts and object verb code in full.

* Fixes: object verb code is now disassembled with the correct engine in the object viewer, object z-plane masks round-trip pixel-perfectly, the v4 sound viewer no longer overlaps the block header, and AdLib music resources are labelled correctly.

* Internal architecture: the editor was split into two assemblies. ScummEditor.Engine holds all of the logic (parsing, codecs, image/sound/text export and import, and game detection) and has no user-interface dependency, so the same engine can back a future non-WinForms front-end; ScummEditor.Gui (now ScummEditor.Gui.exe) is the WinForms interface and only displays the data and triggers engine operations. Each namespace matches its assembly (ScummEditor.Engine.* and ScummEditor.Gui.*). The behaviour is unchanged - every game still loads, edits and round-trips byte-for-byte exactly as before.

* Automated test suite: a comprehensive xUnit project now exercises the engine end to end - game detection, byte-identical save round-trips, the v4/v5/v6 script disassembler, sound and charset extraction, text export/import and the image codecs - run against the real library of games.

1.5.0.0
-------
* Speech file viewer. The standalone speech/effects container of the talkie editions (MONSTER.SOU, or the FM Towns-style "game".SOU) now appears as a node in the tree and lists every voice/effect line with its lip-sync timestamp count, sample rate and duration. Each line can be played in the editor and exported to WAV (one entry or all at once). The file is parsed lazily and the audio is read on demand, so the hundreds-of-MB speech files open instantly.

* CD audio viewer. Releases that ship the CD music ripped as CDDA.SOU now show a node listing each audio track with its start frame and duration; tracks can be played and exported to WAV (44100 Hz, 16-bit stereo), one or all at once.

* MIDI sound blocks now play. The iMUSE tracks use the SMF format 2 that the Windows sequencer rejects; a single-track format 2 is patched to format 0 for playback (the exported bytes are untouched), and MCI errors are now reported instead of failing silently.

1.3.0.0
-------
* Game text translation support. "File > Export game texts" writes every translatable string of the game (dialogues, prints, verb names, object names) to a single .txt file: one line per text with a stable id, control codes as readable tokens ({br}, {wait}, {sound:N}...) and accented characters mapped through a charmap stored in the file header. "File > Import game texts" reads the file back and rebuilds the bytecode - jump offsets and the verb offset tables are remapped automatically when a translation is shorter or longer than the original, and every rebuilt script is re-disassembled and verified before being accepted.

* The charmap is under the team's control: the import rebuilds the character mapping from the "; charmap:" header line, so free font slots can be mapped to new characters or used directly in the text as {0xNN} (e.g. custom ligatures like "Cla{0xC1}e"). On export the translator can optionally paste the charmap of an in-progress translation to keep its custom characters. Lines with nothing to translate (empty names, sound-only strings) are left out of the file, and imported texts are validated against the game fonts, reporting characters that have no glyph.

* Charset (font) editing via PNG. Each CHAR block - or all of them at once through "File > Export/Import game fonts" - can be exported as an editable 8-bit indexed PNG atlas (256 slots separated by divider lines) plus a guide image showing the hex id, the origin mark and the current glyph of every slot. Drawing in an empty slot adds the glyph to the font, extending the character table when needed; untouched slots keep their original bytes, and edited glyphs preserve the font metrics (cursor advance / spacing).

* New OBCD viewer: the object properties (code header, name) and the verb table are shown as fields, with the disassembled verb bytecode below and a label at each verb entry point.

* Script listings now render messages with the same friendly tokens and accented characters used by the text export, instead of raw escape bytes.

* Index file viewers for MAXS (engine limits), DOBJ (object owners/states/classes), AARY (array directory - previously missing from the tree) and RNAM (room names, populated on SCUMM v5 games); the palette offset block (OFFS) also gained a viewer.

1.1.0.0
-------
* Lossless indexed image export/import. Backgrounds and objects are now exported as 8-bit indexed PNGs that store the original palette index of every pixel, and importing reads those indexes back directly instead of guessing them from the pixel color. This preserves the exact index even when the palette has repeated colors, so the image keeps rendering correctly under any of the alternate (APAL) palettes. The old color-matching import and the .idx side files are no longer needed.

* Costumes are exported with their own (costume-local) palette and their relative indexes, also round-tripping losslessly.

* Added detection of Sam & Max installs that use SAMNMAX.SM0 / SAMNMAX.SM1.

* Migrated the editor to .NET 10 and Visual Studio 2022 (SDK-style projects). It now builds and runs on the modern .NET runtime.
